## Швидкий запуск у Windows

1. Відкрити папку `hotel-ais` та запустити **`start.cmd`** подвійним натисканням.
2. Залишити вікно сервера відкритим і перейти на **http://localhost:3000**.
3. Для ролі клієнта натиснути «Увійти» → «Зареєструватися».
4. Для ролі адміністратора використати email і пароль із **`data/admin-access.txt`**. Файл створюється під час першого запуску.
5. Для зупинки натиснути **Ctrl+C** у вікні сервера.

Під час підготовки програми сервер уже запущено у фоні на цьому комп’ютері. Його можна відкрити за тією самою адресою; для зупинки саме цього фонового запуску передбачено **`stop-background.cmd`**. Після зупинки наступні запуски виконуються через `start.cmd`.

Потрібен **Node.js 24 або новіший**. На комп’ютері, де підготовлено проєкт, уже встановлено Node.js 24.10.0, тому додаткове встановлення не потрібне. Окремий сервер бази даних, XAMPP, npm-пакети та інтернет для локальної демонстрації не потрібні. `npm install` виконувати не потрібно.

Альтернативний запуск із термінала, відкритого в цій папці:

```powershell
node src/server.js
```

SQLite входить до Node.js. Повідомлення `ExperimentalWarning: SQLite is an experimental feature` у перевіреній версії Node.js є інформаційним; сервер продовжує працювати. Сторінку потрібно відкривати через адресу сервера, а не подвійним натисканням на `index.html`.

## Правила бронювання й оплати

- Валюта — гривня, суми зберігаються цілими числами в копійках. Сервер сам обчислює підсумок і фіксує тариф у бронюванні.
- Період — від дати заїзду включно до дати виїзду невключно, максимум 90 ночей. Виїзд і наступний заїзд в один день дозволені.
- Неоплачений резерв діє 15 хвилин. Після цього номер звільняється. Один клієнт може мати до п’яти неоплачених резервів.
- Пошук доступності та запис нового бронювання виконуються в одній транзакції `BEGIN IMMEDIATE`, щоб паралельні запити не створили подвійне бронювання.
- Підтверджене бронювання можна подати на скасування до дня заїзду. Погодження скасування та повернення платежу — дві окремі дії.
- Реалізовано повну передоплату й повне повернення. Часткові повернення, зміна дат після оформлення та достроковий перерахунок проживання в цю версію не входять.
- Повторні платіжні події обробляються лише один раз. Оплата, отримана після завершення резерву або після іншої успішної спроби, позначається як така, що потребує повернення.
- Звіти враховують надходження і повернення за датою відповідної операції за київським часом. Завантаження — частка підтверджених, заселених та завершених ночей серед усіх номерів у базі; це навчальний показник без історії ремонтів і змін номерного фонду.


### Локальна демонстрація — увімкнена за замовчуванням

`PAYMENT_MODE=demo`. Усе працює локально. Банківська картка не потрібна, гроші не списуються. Цей режим придатний для показу всієї послідовності на захисті без інтернету.



## Перевірка програми

```powershell
node --test --test-concurrency=1 test/app.test.js
```

Перевірено 19 автоматичних тестів: усі успішні. Тести створюють окремі бази в пам’яті та використовують підставний поштовий сервіс, тому не змінюють робочі бронювання і не надсилають листів. Серед сценаріїв — одночасне бронювання, перетин дат, зміна тарифу, прострочення резерву, повторна та запізніла оплата, повернення, права доступу, CSRF, заселення і виїзд, підпис LiqPay.

Інтерфейс додатково перевірено в Microsoft Edge: каталог, реєстрація, бронювання, відмова й повторна оплата, скасування та повернення, календар, звіти, додавання номера, поштова черга, мобільна ширина 390 px. Зовнішні LiqPay і Resend не брали участі у цих перевірках.

Сценарій цієї браузерної перевірки збережено в `scripts/browser-smoke.mjs`. Для повтору потрібні Microsoft Edge і Playwright; у середовищі підготовки використано вже наявний Playwright. Запуск: `node scripts/browser-smoke.mjs "абсолютний-шлях-до-playwright/index.mjs"`. Ці інструменти потрібні лише для автоматизації браузерних перевірок, а не для роботи програми чи основних 19 тестів.
